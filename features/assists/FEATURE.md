## Code rules

- **Intentional action:** every new action kind adds a descriptor in `runtime/action-descriptors.ts` (verb / explainer / receipt); a kind without one renders a disabled action, never a mystery button. Truncated text with no instant full reveal is banned in this feature. Never fork a second chip.
- **Quiet:** `quiet.ts` owns the windows and the one meaning of the stored value (`null`, `"infinity"`, ISO timestamp). Every client producer emits through `emitAssistTracked` (`redux/emitTracked.ts`), which returns null while quiet; never add a mute that only affects rendering. A source quiet is told from a snooze by `metadata.source_suppression`, never by the timestamp (`source-suppression.ts`). Dock position: `dock-position.ts` + `useDock` from `@ai-matrx/summon/dock`; mobile count: `mobileInbox.ts` (same rows and presentation cycle as the dock, capped by `--visual-viewport-height`).
- **Urgency:** display calls `urgencyFromPriority()` (+ `ASSIST_URGENCY_MIN_PRIORITY`, `ASSIST_URGENCY_META` in `types.ts`), never `priority` directly; icons in `components/urgency-icon.ts`. Producers build the number with `assistPriority(band, rank)`; the aidream twin is `assist_priority()` in `aidream/services/assist_support.py` (raises on an unknown band). Guard: `pnpm check:assist-priority` (fails any bare `priority: <n>` in a producer). The manager's urgency filter is server-side (`minPriority`/`maxPriority` on `AssistsQuery`), so the `priority` column renders the band but does not filter.
- **Navigation:** every Open (`navigate`, `approval_proposal`, "Open all assists") goes through `openFromNotice` (`lib/notice-open/`); dock, chips, cards and window carry `data-matrx-notice-surface`. Guard: `pnpm check:notice-new-tab`.
- **Floating control placement** (`assistClearance.ts`): placement variables (`--assist-dock-slot-*`, `--assist-dock-lift`) live on the dock's own fixed box and are written only when a value changes (a variable on `<html>` restyled the whole page); read them with `dockPlacementVar()`; `html[data-assist-dock-slot]` is the state attribute. The control avoids every `data-agent-input-shell` and `data-assist-dock-avoid` box by its whole box, treats a list row (`[data-row-id]`, group row, `tr`) as standing for its whole list, docks into `[data-matrx-table-footer]`/`[data-assist-dock-slot="footer"]` or the header beside `[data-header-right-set]`/`[data-assist-dock-slot="header"]` when no free spot exists, insets only an inner scroller (never `main`/`.shell-main`), runs one pass per 150 ms quiet period and none while a table is `aria-busy`. Guards in `__tests__/` (`the-assists-control-never-covers-content`, `...-the-composer`, `no-free-spot-docks-the-control-into-the-chrome`, `a-list-without-a-pager-docks-the-control-in-a-slot`, `the-dock-pass-costs-nothing-a-person-can-feel`, `a-route-root-the-size-of-main-is-never-inset`, `clearance-preserves-editable-fields`, `the-assists-control-moves-off-a-control`, `the-pill-is-never-drawn-away-from-its-final-place`); walks `scripts/assists/assists-dock-{cost,slot,views}-walk.mjs`.
- **Write door:** `emitAssist` writes only through `platform.emit_pending_assist` (insert / refresh-own / null-if-addressed-elsewhere; the unique violation never leaves the function), never a client INSERT on `assists_dedupe_pending_key`; same-tab calls for one key share one in-flight promise. Guard: `service.emit.test.ts`.
- **Reads:** the dock and strip wait for auth readiness plus an access token before `list_my_presentable_assists` (authenticated-only grant); `listMyPendingAssists` uses `runWithSessionRetry` once and keeps an unrecoverable `PGRST301` as `SessionUnavailableError`, which the Redux capture boundary ignores while still capturing real failures (`service.auth-retry.test.ts`, `auth-read-boundary.test.ts`). An invalid or stale ledger action is skipped visibly with a developer warning, never `console.error` (it would enter the system-error queue).
- **Actions** are Actions on the app's one registry: provider `assists.actions` (`runtime/assist-action-provider.ts`, `ASSIST_ACTIONS`), ids `assist.<kind>`, programmatic-only (`surfaces: ["invoke"]`), run by id through alchemy's `invokeAction` (content-ir `invoked-actions.ts`); census test `runtime/assist-action-provider.test.ts`. New kind = one handler file in `runtime/handlers/` exporting an `AssistActionDefinition` + one line in `ASSIST_ACTIONS`. `surface_write` goes through `writeToPageThroughDoor`. `run_mandate` is the strict executable action; legacy `launch_agent` stays draft-only until each producer is audited. `navigate` may carry route-specific `label`/`confirm`/`receipt` copy.
- **Editable assists:** text-editable actions use `runtime/action-editing.ts` + `AssistActionTextEditor` (canonical `ProTextarea`); the user's exact revision goes through the same handler and the original payload hash stays the dedupe identity.
- **Display copy:** expiry and producer/source copy are internal lifecycle metadata and never render to users; card metadata is `confidence · date`.
- **Approvals** ride this table (`matrx-user/approval-queue`, `source_key` `approval.<kind>`, `action.kind = approval_proposal`): `features/approvals/registry.ts` is THE list of proposal kinds, `features/approvals/data.ts` the only module there that names `platform.assists`; a new kind ships only when aidream's `RENDERED_PROPOSAL_KINDS` and the registry both have it. Local mechanics: `features/approvals/FEATURE.md`.

## The pieces (all in this feature unless noted)

The Assists manager publishes its current query, view flags, quiet preferences, confirmation and bulk-action state through `matrx-user/assists`. Rows, summaries, counts and suppressions are supplied only after the current query succeeds. A query identity includes the user, filters, pagination and refresh nonce, so a pending or failed query never emits the preceding query’s results as current. `assist_load_state` distinguishes loading, ready and failed; only the current failure supplies `assist_load_error`. The existing canonical table menu consumes the same live scope.

## DB

`platform.assists` migrations: `migrations/platform_assists_ledger.sql`, `platform_assists_absorb_capabilities.sql`, `platform_assists_source_suppression.sql`, `platform_assists_timed_source_quiet.sql`, `platform_emit_pending_assist.sql`. The browser never inserts the unique live-pending index on `dedupe_key` itself. Every absorbed column is read and written by the client (`evidence`, `first_seen_at`/`occurrences`, `resolved_at`, `decision_note`, `is_starred`/`viewed_at`); a column with no consumer is a half-landed migration. `decision_note` is written only when supplied. The whole-source reason lives in base `metadata`, never in `decision_note`.
