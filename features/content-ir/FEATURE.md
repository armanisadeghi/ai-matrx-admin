## Load-bearing invariants

- **Data-only is FAMILY-derived, never a per-row flag.** The manual `metadata.data_only` flag on `content_ir.kind_definition` was eradicated: `content_ir.evaluate_kind_activation` and every frontend consumer (`shape-detail-server.ts`, `admin/KindGateTab.tsx`) derive the exemption ONLY from `metadata.family ∈ {workflow_io, tool_io, action_io}` (DB) / `GENERATED_CONTRACT_FAMILY_VALUES` (frontend, includes `agent_io`). No code path reads or writes a per-row override; no UI offers one. `KindInputForm`'s test bench never blocked on this signal either way — its instance-JSON fallback rests on `emitted_json_schema !== null` alone.
- **One shape, one live kind — enforced at three seams, and they are the SAME rule stated three times (D164).** A hand-authored kind (`metadata.family='user_authored'` OR `metadata.user_authored=true`, not `is_contract_artifact`) may not carry an `emitted_fingerprint` that an ACTIVE hand-authored kind already owns — the render registry (`matchKindForSchema` / `buildKindFingerprintIndex`) is first-writer-wins, so the loser silently DISPLAYS as the winner. Refused at **mint** (`_duplicate_shape_refusal`, matrx-ai `kind_authoring.py`, on `kind_create` + `kind_update_schema`), at **activation** (the `uniqueness` leg of `content_ir.evaluate_kind_activation`), and at the **DB floor under both** (`content_ir.guard_kind_shape_uniqueness()` BEFORE INSERT OR UPDATE — the only leg a second writer, `service_role`, or a future tool cannot walk around). **Change one, change all three.** The scope is deliberately narrow: machine-minted `is_contract_artifact` snapshots and the `*_io` families collide by construction and MUST keep working — never widen it to them.
- **Hosts find regions; the parser owns the inside.** The accumulator (stream) and splitter (DB) detect where a JSON region starts/ends; a fresh parser per region makes single-root true by construction. After a host closes any Markdown, code, XML, JSON, or prose container, both paths run the same `surfaces/embedded-kind-json.ts` recovery pass: every complete JSON object with a direct non-empty `__kind` is promoted to its own Content IR region, while the surrounding bytes remain ordered and lossless. Registered root-kind surfaces and artifacts keep ownership of their nested composition. Generic XML retains ownership while incomplete and excludes fenced code, inline code, comments, and CDATA from recovery; complete bare kind objects remain recoverable. The host remains the region-end oracle until Phase 7.
- **THE FIRST-KEY RULE — a kind is never drawn as raw JSON.** Could be a kind → its loader; known kind → its component; known broken or not a kind → handled (JSON is fine for genuine JSON). "Could" is decided by the first key: nothing raw before it arrives; first key `__kind`, or a `__kind` key anywhere at any time → kind. ONE detector: `surfaces/json-kind-signal.ts`. The accumulator feeds a ```json fence body to the parser character by character (one-line JSON never completed a line), and `BlockRenderer`'s pending gate applies the rule — including to streaming code blocks no parser opened for. Guard: `__tests__/kind-never-raw-midstream.test.ts` (char-by-char, every frame). Open items: `docs/KIND_NEVER_RAW_CHECKLIST.md`.
- **THE BOUNDARY: only real JSON converts (owner, round 10 — supersedes round 9).** Literal, `\u005f`, markdown `\_\_kind` and zero-width inside the key convert (a kind held as a JSON string is read by parsing the JSON); every other spelling in free text (`\"__kind\"` in prose, repr, JS literal, smart quotes, entities, exotic forms) is DETECTION ONLY — the sentinel reports it, every renderer/converter/label/export leaves it byte for byte as written; any region (kind or kindless, live or reload) ends where its own JSON grammar fails.
- **Pushdown discipline:** commit → descend → never re-ask → backtrack. Speculative descent commits a child's kind the instant `{` opens when the parent schema predicts it (`{type:"object",kind}`, single-member `itemKinds`, `expectedRootKind`); `__kind` confirms, re-tags (allowed sibling), or drops THAT node to raw. Objects under a predicting parent need no `__kind` at all.
- **Node-scoped errors never kill a stream.** Duplicate keys, schema violations, disallowed itemKinds → that node goes `raw_object`, the parent keeps parsing. Only grammar errors are region-fatal → the region degrades to a code block.
- **Zero data loss:** unknown keys NEVER merge into snapshot values — they ride `residue.extra` (root residue + per-node residue in `nodeIndex`). Wire round-trip = `reconstructRegionValue`.
- **Stream ≡ static:** the accumulator's streamed envelope and the splitter's one-shot envelope are byte-identical (fingerprint included) — enforced by `__tests__/stream-splitter-parity.test.ts`. Pending-schema nodes resolve to raw at region end so envelopes are deterministic; upgrade-in-place is a live-region feature.

Live-stream consumers read it from Redux via `selectKindEnvelope(requestId, kind?)` (`active-requests.selectors.ts`) — **never a second parallel parse of answer text** (see § No bespoke stream renderers). ## 🚨 No bespoke stream renderers — this is the kiss of death

**A surface NEVER parses, buckets, splits, or routes a live stream itself.** Streamed model output renders through the ONE pipeline: `MarkdownStream` → `EnhancedChatMarkdown` → `BlockRenderer` → `applyIrKindRoute` → the kind's component. That pipeline already owns chunk assembly, region detection, kind resolution, late-schema upgrade, loading states, finalization, and error recovery. Every one of those is a thing your surface will re-solve wrong.

**Banned outside this feature, no exceptions and no size threshold:**

- Calling `useLiveJsonRegion` / `openParseSession`. **`useLiveJsonRegion` is internal.** It is not a public primitive, and no feature may consume it.
- Bucketing raw chunk text into per-phase string buffers.
- Splitting a text buffer into "segments" so each payload gets its own region.
- Reading an envelope and hand-picking a component, or hand-building serverData.
- Deciding when a stream is "done" for render purposes with your own signal.

**Why it is absolute:** the value of this platform is exactly ONE renderer. Bless one bespoke copy and the next agent copies it, and one canonical system becomes thousands of hard-coded ones. A feature being small, a side page, or important is not an exception. **It cannot happen again.**

**Rendering streamed content outside `/chat` — the two sanctioned paths, and there is no third.** Both end at a `requestId` in `activeRequests`, which is what every canonical read is keyed on:

- **The run is client-launched** (a shortcut, `launchAgentExecution`) → you already have the requestId.
- **The run is SERVER-orchestrated** inside a durable pipeline endpoint (`POST /seo/keywords/research` and its kin) → **`adoptForeignStream`** (`../aidream/apps/shared/chat/src/agents/redux/execution-system/thunks/adopt-foreign-stream.ts`). Pass the consumer it returns to `callApi`'s `consumeStream` option; the endpoint's NDJSON body goes to `processStream` instead of being drained by callApi, so the agent's content lands in `activeRequests` exactly as a chat stream does. Your surface still sees every event via `onEvent` for its OWN typed progress. Then: `<MarkdownStream requestId />`, `selectKindEnvelope`, `selectAnswerText`. **The row you render from can be reaped/reset out from under a mounted viewer — the disappearing-run class. Read [`/Users/armanisadeghi/code/common-docs/systems/architecture/execution-runtime/LIVE-RUN-RETENTION.md`]/Users/armanisadeghi/code/common-docs/systems/architecture/execution-runtime/LIVE-RUN-RETENTION.md) before adding any adoption, reap, or `removeRequest` call.** A surface displaying MORE THAN ONE run (or runs beside API data) keeps its set in the `runSets` slice and renders `<RunSetDisplay setKey/>` (`../aidream/apps/shared/chat/src/agents/components/live-run/RunSetDisplay.tsx`) — never hook-local run lists.

That second path is THE fix. The one real violation existed because a pipeline stream had no requestId and the doctrine's only answer was "give it one" with no mechanism. There is a mechanism now. Server-side twin: aidream's `stream_agent_as_blocks` (`aidream/services/ai_execution/block_stream.py`) makes those pipeline runs emit real `render_block` events with envelopes rather than bare chunks — engaged automatically by `run_one_agent(stream_output=True)`.

**A child agent streaming inside a parent's request (2026-09-30) is not a third path — it is a SLICE of the first.** A collaboration/plain `agent_call` child's blocks live in the parent request (`renderBlockOrder[blockAnchor .. blockEnd)` of the `sub_agent` op whose `toolCallId` is the card); the transcript hides that range (D209). The owning card renders it with `<MarkdownStream requestId={parent} agentCallId={callId} />` — `selectAgentCallChildSlots` feeds those blocks to the normal BlockRenderer path, so kinds route as in the parent. Never hand the child's joined text to `content` (`CollabCallCard`, `AgentCallInline`; guard `chat-markdown/__tests__/agent-call-child-renders-through-the-engine.test.tsx`).

**Enforced:** `matrx/no-bespoke-stream-renderer` (ESLint, **error**) — importing `useLiveJsonRegion` / `openParseSession` outside `features/content-ir/` fails lint. The owed rule is no longer owed.

**The thinking-leak twin (2026-09-11) — a live stream through a PLAIN markdown component.** The lint above catches a hand-rolled parser; it does not catch the quieter shape that bit Vision Interview's `LiveTurnCard` and `CollabCallCard`: raw chunk text handed to `BasicMarkdownContent` / `ConfigurableMarkdownContent` with `isStreamActive`. Studio twin: `apps/workflow-studio/src/lib/no-thinking-at-eye-level.test.ts` in aidream.

**The flattening twin — a shaped job run headless-for-TEXT — is enforced twice.** Runtime: `execution-system/thunks/structured-output-flattening.ts` screams (DECLARED + HARVESTED) from inside `runHeadlessAgentJson`. Static: **`pnpm check:flattened-shapes`** (`scripts/check-flattened-shapes.ts`) finds every `expect: "text"` / `run<string>()` site naming a `mandateKey`, reads the key's `output_kind` from the LIVE catalog, and reports each text run on a structured kind with file:line and the same remedy sentence (`FLATTENING_REMEDY`, one source). `null`/`text`/`markdown` = prose (a text run is correct); anything else including `json` = a shape. ## 🚨 THE RENDER RATCHET — a streaming block only moves forward

A streamed block's render advances text → loader → generic → the kind's component and never steps back mid-stream unless we are absolutely confident something has gone wrong. Three layers hold it, each in a package:

- **Identity** — `EnhancedChatMarkdown` keys blocks by POSITION (`block-${index}`), never content: a content-prefix key remounted every text/kind block per token for its first 100 characters.
- **Arrival** — the live accumulator (`@ai-matrx/chat` `stream-block-accumulator.ts`) never retracts a drawn block: the nascent-JSON hold judges the whole block (it used to read the last line, so each nested `{` retracted the region and the component remounted once per item) and holds a whitespace-only new tail instead of drawing and retracting it.
- **Decision** — `BlockRenderer` runs `decideBlockRender` per frame, then `advanceRatchet` (`@ai-matrx/rich-content` `block-registry/render-ratchet.ts`): a backward frame keeps the last good decision (same element, same props). It lets go when the block SETTLES (final value is the truth — a final-invalid payload falls back then), when a different block takes the slot, or mid-stream after `RATCHET_RELEASE_MIN_FRAMES` (120) distinct frames AND `RATCHET_RELEASE_MIN_MS` (8 s).

Partial values are progressive by default: `isPartialReadyKind` is true unless a kind says `partialReady: false`; `ProvisionalKindBoundary` withholds a kind whose component throws. Guards: `stream-never-goes-backwards.test.ts` (chat), `render-ratchet.test.ts` (rich-content), `features/content-ir/__tests__/stream-mount-once.test.tsx` (real accumulator → real renderer, one root: component mount count is 1).

## 🚨 THE CANONICAL COMPONENT LAW — one shape, one component

**No bespoke stream renderers has a twin, and it is violated far more often: a registered shape may be rendered ONLY by its kind component.** The stream rule protects how data ARRIVES; this one protects how it LOOKS. Both exist for the same reason — one implementation that everyone improves, instead of N that each rot alone.

**The law.** If a kind is registered, its component renders it **everywhere** — chat, a live run, a form, a side panel, a preview card, a summary row. A hand-built renderer for that shape is **banned**, no matter how small, how "just a preview", or how specialized the surface feels.

**Why, concretely.** The duplicate always ships new bugs the canonical one already solved, it silently misses every later improvement, and it doubles the cost of every future change. Real example (2026-08-11): `features/marketing/content-plan/components/BriefEditor.tsx` re-implemented the `page_brief` kind by hand _on the very page whose run renders `PageBriefBlock` in the window beside it_ — same data, two renderers, two designs, and the duplicate crushed full-paragraph directives into one-line textareas.

**The four things people reach for a bespoke component to get — all of them belong IN the kind component:**

| You need                                               | Do this                                                                                                                                                                                  |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Only PART of the shape (just the angle, just the list) | **Split the canonical component into per-field child components; the parent composes them.** Render the child. Never re-render a slice by hand.                                          |
| It editable — add / remove / reorder / sort / filter   | Build it into the kind component. That is what kind components are FOR. Exemplar: the keyword kinds.                                                                                     |
| An action on it ("Use this brief", "Apply")            | A kind action on the app's one action registry — [`react/actions/kind-action-provider.ts`](react/actions/kind-action-provider.ts) + `useKindActionRunner`. Not a button on a bespoke card beside it. |
| It to look different here                              | Props on the canonical component. If the difference is real, every surface benefits from it.                                                                                             |

**Parent/child is the escape hatch, and it is the ONLY one.** A `page_brief` is angle + brief + must-not-cover + concerns. Wanting those in four places is a reason to build four child components under one parent — not a reason to hand-roll a fifth renderer.

**Exceptions exist only with the owner's explicit approval, per surface. No agent may grant itself one.** Not using the canonical component is against the rules — full stop.

## 🚨 THE FLOOR — an unregistered shape still looks good

**The guarantee changed on 2026-08-18, and this is the sentence to read: a shape no longer has to be REGISTERED to render well.** `MarkdownStream` is unconditional — any text in, good output out, no registration — and that is exactly why it never fails. The Shape System is a REGISTRY, so looking good depended on three independent things all being true (a curated `output_kind` rather than an auto-derived `action_io_*` / `workflow_io_*` contract kind; an ACTIVE web `kind_component`; a payload that validates), and missing any one dropped the payload to the floor. **The floor was `JSON.stringify` in a ```json fence.**

**The floor is now `StructuredValueView`** (`components/official/structured-value/StructuredValueView.tsx`): ANY JSON value as a human document — long strings as prose through the canonical markdown renderer, uniform object arrays as a sortable/filterable table, scalar arrays as lists and short ones as chips, nested objects as titled sections with humanized keys, `file_id` / media refs through `InlineMediaRef`, UUIDs and dotted enum reprs given their real treatment, empty fields as one word. It is recursive with a size bound (past ~40 KB serialized it renders in the capped density, where every cap carries an in-place "+N more"), it strips the internal `__kind` discriminator from what the reader sees, and it always offers **"Show the raw data"** — the JSON inspector, one click away, for US.

**A curated `kind_component` is now an UPGRADE, never a prerequisite.** THE CANONICAL COMPONENT LAW is unchanged and still wins: a registered kind's component renders it everywhere. This is only what happens BENEATH that decision — never a second renderer for a shape that has one.

**It is not a new engine.** The recursive value renderer already existed as the tool-result field library (`../aidream/apps/shared/chat/src/tool-call-visualization/result-fields/` — `detectResultShape` + `ResultValue` + `KeyValueGrid` + `ResultTable` + `ResultMedia` + `ResultJson`). THE INVENTORY LAW: the defect was that the Shape System's floor IGNORED it, not that it did not exist. `StructuredValueView` is the platform-wide door onto it plus the document framing and the raw escape. **That library is a PLATFORM primitive, not a tool-call-visualization one** — its physical home should move to `components/official/`; until it does, import it and do not fork it.

**Where the floor is wired (every fallthrough, no exceptions):**

| Fallthrough                                                                                 | Was                                                                                   | Is                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `react/kind-route.ts` R6 generic route → `GenericStructuredBlock`                           | a `JsonInspector` tree under an "Unverified shape — no renderer is registered" banner | the document; the honesty moved to a muted footer beside the raw escape, and the block renders **bare** (the host owns the chrome — it used to double-card inside `/shapes`) |
| `studio/components/KindInstanceRender.tsx` unroutable path (**15 surfaces**)                | a ```json code block, or a `<pre>` for a non-object value                             | the document                                                                                                                                                                 |
| `features/workflow-runtime/components/readout-parts.tsx` (`JsonBody` / `SettledOutputBody`) | `JSON.stringify` in a fence through `MarkdownStream`                                  | the document (settled agent text that IS a JSON document is parsed and handed to it too)                                                                                     |
| `components/mardown-display/blocks/agent-result/AgentResultBlock.tsx`                       | every `structured_output` fenced as JSON                                              | fenced ONLY when it carries a `__kind` the pipeline can route; otherwise the document                                                                                        |

**The honesty never left.** The footer names the shape in human words ("Study pack set — no custom view yet", or "a custom view is registered but held inactive" when a row exists and is held), keeps the exact slug on its `title`, and the raw data is always one click away. R6's rule — never claim a shape has a renderer when it does not — is intact; what changed is that the reader no longer pays for it.

**Two shared-library bugs this uncovered, both fixed in `result-fields/`:** `isPlainObject` compared prototypes by IDENTITY, so any object from a different realm — which is every value that went through `structuredClone`, i.e. the envelope round-trip `reconstructRegionValue` runs on EVERY value the floor renders — fell to the `json` branch, back to a tree. And `EmptyResult` at `full` density is a 40px centered block, so an ingest step with an empty `errors` array opened with a giant "No result returned" above the material; an empty FIELD is now one word.

**Corollary — do not wrap it either.** A kind component brings its own spacing, border, and background. Nesting it in a padded `<div>` inside a card inside a panel produces the visible box-in-a-box with a dead band around it and two fighting background tokens. A host that already draws chrome renders the content **bare** (exemplar: `LiveRunDisplay`'s `variant="bare"` inside `LiveRunWindow`). See [`features/window-panels/FEATURE.md`](../window-panels/FEATURE.md) § THE FLOATING LAW for the run-window half.

## A deliberate switch-off survives a bulk activation (2026-10-14)

Every `content_ir.kind_component` switch-off, by any path, stamps `metadata.deactivated_at` and `metadata.deactivated_reason` (DB trigger `zz_deliberate_off_survives_bulk_on`). Rows whose notes start "SWITCHED OFF" or "Deactivated" count as marked too. A blanket `update ... set is_active = true` (no signed-in person) leaves marked rows OFF and raises a WARNING naming them. A person's activation, `set local content_ir.activation_ok = '1'`, or an update that clears `metadata.deactivated_at` activates and clears the marker. New rows are born active; activation by a person is never refused. ## Standing laws (survivors of the retired change log)

- **Zero prefetch.** A session that never meets a `__kind` performs ZERO Content-IR fetches — no light catalog, nothing on page load or auth events. The first fetch fires at the kind SIGNAL (`__kind` key, a compiled detection surface, or a caller-declared expected kind), per slug, while the loading component covers the wait. XML/fence finalization warms `kind_surface` only after `kindRegistry.hasBeenDemanded()`. Guard: `__tests__/zero-prefetch-law.test.ts` replaces the one browser Supabase client with a recorder and fails on any Content-IR read.
- **Lazy registry.** `ensureWarm`/`refresh` load only the light catalog (slug + `metadata->>loading_component`); heavy data (`data`, `emittedJsonSchema`) rides the per-kind cold tier, which also serves compiled kinds so a DB row still overrides a compiled schema. `isKnownKind` (compiled ∪ catalog ∪ cold) is the membership predicate. Warm list reads page through `readAllRows`. A refused or empty registry read is never a verdict (a miss expires; `refresh(maxAgeMs)` + the `content-ir:kind-definitions` invalidation re-reads).
- **One loading sequence.** A `__kind` block behaves identically whether it arrives by live stream, DB reload or workflow transport: kind key detected → the kind's loader at once → the real component from the first renderable unit, growing; the loader never returns. `BlockRenderer` requests schema + component for every envelope kind (`ensure-kind-renderable.ts` in `@ai-matrx/rich-content` `src/kinds/react/`); a hard artifact-loading gate never applies to kind blocks. The loading-slug list is ONE list (`KIND_LOADING_SLUGS`, `react/loading/kind-loading-slugs.ts`, compiled in; `pnpm check:loading-slug-twin` diffs it against aidream's mirror).
- **The kind slot.** A reserved place never moves what is above it: `KindSlot` (`@ai-matrx/rich-content`, `src/kinds/react/slot/KindSlot.tsx`) is one root element across `reserved → arriving → settled → failed`; the placeholder is a phase of the kind's silhouette, never a second authored component, and `reserved` goes still (no shimmer, no spinner).
- **One type.** The generated registry types (`kinds/generated/kinds.generated.ts`, `pnpm check:kind-types`, DB is the source of truth, never hand-edited) are the ONLY kind payload types in this repo; a bridge or renderer declares no private payload interface (`pnpm check:kind-type-twins`, allowlist `scripts/shape/kind-type-twins-allowlist.json`).

- **`kindState` gates.** Save-from-chat and artifact materialization (`studio/message-kind-instances.ts`, `features/canvas/materialization/planMaterialization.ts`) hard-refuse `raw` and accept `unverified`; `makeCompleteEnvelopeBridge` carries the same refusal. `=== "resolved"` gating is the 2026-08-28 outage.
