## Routes
| Route | File |
|---|---|
| `/intelligence` — the directory in the live registry's shape: a section per Domain (its own jobs as the first card), a card per Feature holding jobs at or below it with one collapsible row per child node at any depth, then Everywhere, Yours, Your organization, Unplaced and (admins) Test fixtures. `?mandate=<key>` is every job link's door: the server reads the job's node and redirects there, carrying every other param — or to `/research/topics/<id>/intelligence` when the link has `topicId` and the node is Research or below. `?domain=<slug>` scrolls to a Domain | `app/(core)/intelligence/page.tsx` → `IntelligenceIndex.tsx` (+ `index-model.ts`, `feature-icons.ts`, `resolve-destination.ts`) |
| `/intelligence/[feature]` — any registry node by slug at any depth (`seo`, `seo-keywords`), with a breadcrumb header (Marketing › SEO › SEO Keywords), or a lane (`everywhere`, `yours`, `your-organization`, `unplaced`, `fixtures`). A focused job that sits elsewhere redirects. A code feature id (`podcast`) opens the deepest node its declared jobs share; `unassigned` opens `unplaced` | `app/(core)/intelligence/[feature]/page.tsx` → `IntelligenceTargetRoute.tsx` |
| `/intelligence/[domain]/unassigned` — retired, redirects to `/intelligence/<domain>` | `app/(core)/intelligence/[feature]/unassigned/page.tsx` |
| `/research/topics/[topicId]/intelligence` | `app/(core)/research/topics/[topicId]/intelligence/page.tsx` → `features/research/components/intelligence/TopicIntelligencePage.tsx` |

`featureIntelligenceHref(slug, { mandateKey, context })` / `intelligenceHref(key, context)` (`hrefs.ts`) build links synchronously with no placement: a job link is `/intelligence?mandate=<key>&<context>`. The same `intelligenceHref` is registered with `@ai-matrx/chat` (`registerSurfaceIntelligence`, ≥ 0.8.43) for the Agents menu's Page intelligence rows.

## Placement comes from data (plan: common-docs systems/intelligence/mandates/projects/intelligence-from-data)
- A job's node: `mandate.intelligence_placement` (its surface's `ui.ui_surface.taxonomy_node_slug`, else its own `mandate.definition.taxonomy_node_slug`); the tree: `platform.taxonomy_node.parent_id`. Read by `placement-data.ts`, cached per session by `usePlacement.ts`, arranged by the pure `placement-model.ts` (no slug, rule or key namespace lives in code).
- No node: a code job → Unplaced; a shortcut whose surface is NULL → Everywhere; other soft jobs → Yours (the viewer made it) or Your organization; `metadata.fixture` → Test fixtures.
- Roll-ups: per-surface versions carry `source_mandate_id` → their anchor; one roll-up row ("81 versions") sits at the anchor's node and expands into the anchor's split card plus a line per version (`PlacedJobs.tsx`). A version whose surface carries a node also shows there.
- Guards: `__tests__/placement-model.test.ts` (random slugs; any hand map fails it) and `pnpm check:intelligence-placement-from-data` (two+ live slug literals in one list, a key pattern beside a slug, a static registry import, or a retired name, under this folder and `app/(core)/intelligence`; UNMEASURED without the DB = red; `--self-test`).

## Map
- `FeatureIntelligence.tsx` — page body, feature-agnostic. Props: `feature`, `context`, `focusMandateKey`, `runOverrides`, `showTitle`. Seat: person, or organization when the viewer administers the active (non-personal) organization.
- `service.ts` — one definition read over the page's exact keys (its node and every node below it, or its lane), then ONE `public.mnd_member_list` read per lane (holder-neutral: agent or workflow) filtered to the exact visible keys (`select` filter) — never one per prefix. The server pushes that exact-key filter into the row builder (`mandate._member_list_rows(…, p_keys)`, `migrations/mnd_member_list_key_pushdown_2026_09_25.sql`): marketing's read went 2.07 s → 0.52 s. The page reads once, for a settled seat (after the org bootstrap; the role only gates the organization level) — it used to read three times on load.
- `IntelligenceJobCard.tsx` — one job, a compact row (mandate: name, status, Mandate Peek, new tab | holder: peek, new tab, deciding level) that expands into the split card (Can use / Makes / Runs in left; holder with Duplicate & modify, Use my own, Reset, and the System → Organization → You ladder right). Text never wraps: one line, ellipsis, full text in the tooltip; halves stack under `md`. Pieces in `job-card-parts.tsx`.
- `IntelligenceSearch.tsx` + `useIntelligenceDirectory.ts` — the one search on every Intelligence page (`?q=` in the URL via `history.replaceState`, so Back keeps it): the directory filters everything; a feature page filters its own jobs and lists other features' matches under "Everywhere else", each opening its page with the job focused. One cached index for all pages.
- `useIntelligenceActions.ts` — Duplicate & modify copies the deciding holder snapshot, including pinned agent/workflow versions, then binds and verifies the copy at the viewer's rung before opening it. The deciding rung's map and settings follow the copy. Use my own uses `HolderAssignment` in `UseOwnDialog.tsx`; Reset removes the viewer's binding and reveals the inherited choice. All writes use `putMandateBinding`/`removeMandateBinding`.
- `registry.ts` — `DECLARED_FEATURES` (every CODE feature's places map, keyed by code id), `featurePrefixes` (which keys a code feature's own controls list), `declaredPlacesForKeys` (the declared places that run a page's jobs).
- `places.ts` + `PlacesMap.tsx` — where each job runs. Sources: DECLARED feature maps (every map is listed in `registry.ts`, 45 features as of 2026-09-25) and REGISTERED screens (`ui.ui_surface_agent_role` ⋈ `ui.ui_surface`, read by key prefix in parallel with the jobs and kept to the jobs the viewer can see). Workflow Studio places (aidream `apps/workflow-studio`) carry `app: "workflow-studio"` plus `calls`/`server`; the guard reads them from the sibling checkout (`AIDREAM_DIR`, UNMEASURED when absent) and follows each call to the server file that routes it and names the job. Unnamed jobs read "Not recorded yet" — the honest state for jobs that run only in the background, the Chrome extension or the desktop app.
- `MandateDoorLink.tsx` registers page-level feature doors without rendering a second header control. `page-intelligence-doors.ts` publishes those registrations to `PageIntelligenceSection`, at the bottom of the existing header Agents menu. It combines declared route jobs, live mandates, and registered feature places into compact links that open a new tab. The inline variant remains a direct new-tab link. `IntelligenceIndicator.tsx` remains beside individual AI controls; its popover links also open new tabs. The Workflow Studio has its own door in aidream (`src/components/layout/intelligence-door.tsx`, side nav).

## Adding a feature's places
Write `<feature>/…/intelligence-places.ts` (a `FeaturePlaces`: places with `sources`, plus `roots` to scan and `aliases` for key maps/constants the code reads jobs through) beside the code that runs the jobs, and list it in `registry.ts`. `__tests__/declared-places.test.ts` proves it: every place job is named in its sources, every source names one, and every component under `roots` that names a job is mapped. Keep the map's imports light — it loads with every Intelligence icon (never import a hook module for an alias; name the key instead).

## Landmines
- The Intelligence icon is `INTELLIGENCE_ICON` from `components/icons/domain-icons.ts` (lucide BrainCircuit, reserved — `pnpm check:reserved-icons`); an agent holder shows `AGENT_ICON`.
- The member list names `holderId` for workflows as the workflow definition id; agent pins come from the ladder (`fetchMandateLadder`) at duplicate time.
- A pinned workflow copy duplicates the selected workflow version; an unpinned workflow copy duplicates the live definition.
- An organization-level copy is created by the admin; members can use it only if they can open it (the server's answer is shown).
- The research topic's own per-role choice (`rs_topic.agent_config`) runs ahead of every ladder rung for that topic. The page shows it as a separate layer — always, including a pin that names the agent the mandate picks today (the server collapses it now, but it takes over the moment the mandate choice changes, so "Use my own" and "Duplicate & modify" remove it after binding). A successful replacement is bound and verified before the topic choice is removed with a guarded JSON merge; a rejected replacement leaves that topic choice in place. A confirmed missing, inactive, or archived topic agent is shown as needing attention and duplication copies the inherited mandate holder. A pending or failed lookup still copies the recorded topic agent ID; failure leaves the topic choice intact.
- The Intelligence icon is an owner-approved exception to "disclosure adds no visible content" (Arman 2026-09-25); it is a management door, not a disclosure roster.
